# Documentando o Fluxo de Versionamento



## Sessão 1: O Passo a Passo da Criação e Envio



### O Início: Como você cria um repositório vazio diretamente no GitHub? Quais configurações iniciais são necessárias?



Primeiro eu acesso minha conta no GitHub, vou no lado supeior direito e clico no ícone de + (mais) e vou no novo repositório, após isso, irei dar um nome ao meu repositório *(Ex. Banco de Dados da Cruzeiro do Sul)* na descrição irei informar o objetivo ou dar um breve resumo do meu projeto. Nas (configurações) você pode colocar Público ou Privado seu projeto, isso permite que outras pessoas pode ver seus projetos, já na parte (Adicionar arquivo README) está desligado, você vai pressionar em ligado, pois, os arquivos README podem ser usados ​​como descrições mais longas, depois você vai clicar em criar repositório. Isso vai autorizar que crie um repositório para colocar projetos. Agora, se fosse uma criação de repositório vazio, você não marcar nenhuma opções nas (configuração), só o nome do repositório, criará um repositório completamente vazio.



### A Conexão: Explique o processo de vincular uma pasta local no seu computador a esse repositório remoto criado na nuvem.



Você vai acessar seu github.com e clique no botão verde "New". Após isso, Digite o nome do repositório e escolha entre Público ou Privado. Clique em "Create repository" para gerar o projeto. Na tela inicial, clique no link "uploading an existing file". Agora, você vai assastar os arquivos escreva a mensagem e clique em "Commit changes", isso vai vincular com sua pasta local do seu computador.



### O Primeiro Envio: Descreva a sequência exata de ações ou comandos necessários para pegar os arquivos da sua máquina e fazer com que eles apareçam na página do seu repositório no GitHub.



Abrir o aplicativo e selecionar a pasta do projeto no seu computador.



O programa vai listar automaticamente todos os seus arquivos na tela.



No canto inferior esquerdo, escreva um título para o seu envio (Ex: Banco de Dados da Cruzeiro do Sul).



Clique no botão azul "Commit to main" no final da página para salvar as alterações.



Por fim, clique no botão "Publish repository" (ou "Push origin") no topo da tela para enviar tudo para o site do GitHub.

## Sessão 3: O Mapa das Atualizações (Commits e Pushes)



### GitHub Online: Como e quando atualizar um arquivo diretamente pelo navegador? Quais as limitações?



Você pode acessar seu projeto e clicar no seu arquivo, após isso clica no ícone do lápis para editar o projeto, sempre ver os arquivos de textos. A limitação é que as atuializações é um por vez, não dar para gerar varios códigos de uma vez só e para projetos grandes e proscesso é lento.



### Git via Linha de Comando (Terminal): Como funciona o fluxo de atualização utilizando os comandos de texto? Por que essa é a forma mais tradicional?



Você pode prepara as alterações, salva um arquivo local com uma mensagem e envia os arquivos para a nuvem. A forma original do Git é extremamente rápida leve e universal.



### IDEs (Ex: VS Code): Descreva a sua experiência utilizando a interface gráfica do próprio editor de código para fazer os commits e pushes.



O meu acesso ao VS Code é pratica bem dinamica, pois é os arquivos estão mais facieis de ser modificados, quando você salvar os projetos já é ficam mais facieis de rodar, quando você digita a mensagem do commit em uma caixinha de texto e clica em botões visuais (como "Commit" e "Sync Changes") para salvar e enviar o código sem precisar sair do editor.





### GitHub Desktop: Explique como essa ferramenta dedicada facilita a visualização e o envio de alterações.



Já o GitHub Desktop é uma ferramenta para quem não gosta de usar o terminal, pois, essa ferramenta é totalmente visual, ela mostra de forma colorida e clara o que foi adicionado (em verde) ou deletado (em vermelho) no código. O envio é feito de forma simples, é só através de cliques em botões grandes.





## A Filosofia da Atualização: Finalize o texto explicando por que é crucial atualizar o repositório continuamente e em pequenas partes, em vez de enviar tudo de uma só vez no final do mês.



**É crucial, pois as tecnologias e informações mudam constantemente, sendo importante adicionar ideias novas aos projetos para mantê-los atualizados. Além disso, enviar em pequenas partes evita a perda de arquivos, isso pode dificultar para construir ou recuperar os projetos pedidos.**
